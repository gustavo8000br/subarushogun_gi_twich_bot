Project #5 (owner gustavo8000br) mirrors the stories; @devops updates it on EVERY story/issue event (new story, status change, gate verdict, issue created/edited, commit/PR, decision). Owner rule 2026-10-27.

**Why:** the owner prioritizes by moving cards; overwriting his moves from the repo loses his decisions.

**How to apply:** before each sync read the board; treat owner values in Status (Situação), Prioridade, Ordem and card position as authoritative; on disagreement REPORT the conflict, never revert. Routine: `.local/board-sync/` (`build-load.mjs` -> `load.json`, `sync.mjs --dry-run` then `--limit N`, conflicts in `report.json`; `--accept-repo ID` only with explicit owner OK). The default `Status` field cannot be renamed through the API (name is ignored); options can be replaced while preserving IDs via `updateProjectV2Field` with `id` per option. Native workflows and views are web-UI only. Side effect seen 2026-10-27: setting Status=Concluído on an issue card makes the native Project workflow close the issue (closer ProjectV2, as the owner account) — #82 was closed this way while its commit was still unpushed (reopened 2026-10-27, card back to Em revisão).

**Rule (owner, 2026-10-27):** moving a card to Concluído must NOT be used before the PR is merged while the native workflow "Close issues when status changes" (Auto-close issue) is enabled; the owner will disable it in the web UI (Project #5 -> ... -> Workflows). Done = merged; until then keep Em revisão. If the workflow is still on, never set Concluído on an issue card ahead of merge; in overrides.json use Em revisão. Seen 2026-10-27 (#92/#93): a native auto-add workflow puts new repo issues on the board with Status=Backlog right after `gh issue create`, so sync sees them as existing items. When a design "rascunho" card becomes an issue before @sm updates the design, record `ID\tN` in `created.tsv` (build-load uses it). In zsh never put flags in a `$VAR` (no word splitting); use functions or literal args. Run `BOARD_DATE=<today> node build-load.mjs` — without it the date defaults to 2026-10-24 and dry-run shows a false "Atualizado em" diff on every item. Issue audits: candidate list goes to `.local/board-sync/issue-audit-<date>.md` before any close; body edits via a script that saves `audit-body-<n>-before.md` backups (2026-10-27 audit closed nothing; #40/#73/#74 got traceability sections). CI (`ci.yml`) only runs on `pull_request`→main or `workflow_dispatch`, so a branch push produces no run. GitHub sub-issues have ONE parent: `gh issue edit <new> --add-sub-issue N` silently moves N off its old parent (2026-10-27: #74 left #69 for #80) — say so in the issue body. Items outside the design/inventory (roadmap parents, e.g. #94) go in `.local/board-sync/extras.json` (build-load appends them); #94 was NOT auto-added by the native workflow, sync added it. When the owner has just moved a card (e.g. #57 to Rascunho), never set Status even if Orion relays an older wish; leave the repo value so sync records the conflict, and edit only text fields. When splitting a "Por quê" update, prepend to the old text instead of replacing it. See [[pathspec-commits]].
