## Problem

The owner requires Next.js to serve the overlay page in development and production. Fastify remains the API, data, domain and Twitch authority. The overlay must stay live as account and queue data changes, and keep its existing capability contract.

## Proposed contract

The path remains `/overlay.html?ref=<reference>#<capability>`, with Next as the document server in all modes:

| Mode | `GET /overlay.html` document | Read API | Issued origin |
| --- | --- | --- | --- |
| Local development | Next dev over HTTPS, bound to `127.0.0.1`, rewrite `/overlay.html` to `/overlay/` | Same-origin `/overlay/api/*` through Next, proxied to local Fastify HTTPS | Next loopback HTTPS, `NEXT_DEV_PORT` |
| Local production | Next Node server over HTTPS on container port `3000`, mapped to public host `APP_PORT` | Same-origin `/overlay/api/*` through Next, proxied over trusted loopback HTTPS to private Fastify `API_PORT` (`3109`) | Next HTTPS, `PUBLIC_BASE_URL` |

The path, non-secret `ref`, fragment secret, persisted hash, bearer header, single-widget read scope, revocation/rotation, and admin-session separation remain unchanged. The browser renderer reads the current projection once per second with caching disabled and refreshes on visibility return; Fastify calculates current-account/queue values. Next only serves the page/assets and forwards the read. The secret never enters a query/path, logs, cache, or projection response. Local HTTPS uses the CA certificate generated by bootstrap. Do not permit HTTP, a LAN host, permissive TLS fallback, or a cross-origin production API. Compose publishes only the existing product port on host loopback; Fastify remains inaccessible directly from the host.

Previously issued development URLs used the API origin. In dev mode, `/overlay.html?ref=...` on Fastify returns a temporary redirect to the configured local Next origin without including the fragment in the `Location`; the browser retains the fragment. Local Next binds only to `127.0.0.1`; only explicitly detected Codespaces uses `0.0.0.0`. In production Next owns `/overlay.html` and `/_next/*`; before panel cutover it forwards the remaining legacy panel paths/assets through to Fastify. `/api/*`, `/overlay/api/*`, `/health` and `/callback` are proxied to Fastify. The single product URL remains unchanged.

## Options

| Option | Selection | Effect |
| --- | --- | --- |
| **A — Next page server, Fastify API (selected by owner)** | Next serves `/overlay.html` in development and production over the existing HTTPS product port; same-origin reads proxy to private Fastify. Existing capability and live polling are preserved; the legacy panel is temporarily forwarded until cutover gates pass. | Keeps the document on Next, data/domain ownership on Fastify, one public port, and existing links. Requires a production Node server, TLS trust, route precedence, container startup/health, and native OBS/CEF validation. |
| B — Fastify as document server | Fastify serves the page in all modes; Next does not host it. | Conflicts with the owner's explicit direction. |
| C — Remove the bearer capability | Adopt the capability-free projection proposal in OPS-13/#57. | Changes authorization and widget-level isolation; requires separate architecture decision, threat analysis, security review, replacement criteria/tests, and human approval. |

**Decision:** A, selected by the owner. Next static export cannot provide the required production rewrite/runtime behavior, so production uses the Next Node server. Next rewrites send API and callback traffic to Fastify; a one-second client poll keeps account and queue projections current. **Architectural inference:** a private Fastify listener plus Next HTTPS gateway preserves one local public origin while keeping domain/data decisions out of Next. CEF certificate trust and real OBS compatibility still require native validation and cannot be inferred from normal Chromium. The Fetch Standard specifies that a redirect whose `Location` lacks a fragment inherits the original URL fragment, preserving existing development links without sending the capability to the server. Sources: [OBS Browser Source](https://obsproject.com/kb/browser-source), [Next.js self-hosting](https://nextjs.org/docs/app/guides/self-hosting), [Next.js rewrites](https://nextjs.org/docs/app/api-reference/config/next-config-js/rewrites), [Fetch Standard — redirect fragment](https://fetch.spec.whatwg.org/#concept-location-url).
