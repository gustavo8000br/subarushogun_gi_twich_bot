# Runtime and boundaries
[Português brasileiro](../pt-BR/front-end-architecture/runtime-and-boundaries.md)


OPS-15 replaced the earlier static-export plan (historical) with a two-process runtime. In production the Next.js App Router application in `apps/frontend/` runs on the Next.js Node server over local HTTPS on `PANEL_PORT` (3000 in the container, published only as `127.0.0.1:${APP_PORT:-3000}`), and Fastify runs as a separate process on loopback `API_PORT` 3109; `apps/infra/scripts/start-product.mjs` supervises both. There is no static export, public hosting or new public port. `npm run dev` launches both Fastify (loopback, port 3109 by default) and Next, using a dev-only same-origin proxy to the explicitly validated loopback Fastify origin; that proxy exists only in development. In Codespaces, the launcher passes Fastify the exact HTTPS origin for the forwarded Next port so local session and CSRF checks accept the browser's forwarded origin; other origins remain rejected, and production retains its localhost-only rule. On first run it copies `.env.product.example` to ignored `.env.product.local` without overwriting an existing file, then reads `DATABASE_URL`; with an empty URL the launcher provisions its isolated development database. This file is separate from AIOX's root `.env`. The command creates isolated TLS material under `.local/dev-tls`. The build-time Next/transpilation/bundling pipeline is the narrow exception to the previous no-framework/no-bundler constraint; application source remains JavaScript ESM with JSDoc, with no TypeScript adoption.

Production uses `trailingSlash: false`. The Next production rewrites send `/api/*`, `/overlay/api/*`, `/health` and `/callback` to `FASTIFY_INTERNAL_ORIGIN` (default `https://localhost:3109`), which must be HTTPS on a loopback host with an explicit port. Fastify accepts a loopback Host on either the public port or `API_PORT` (`backendPort`), accepts only an HTTPS loopback Origin on the public port, then applies session and CSRF checks. The OBS overlay is served directly by the Next `/overlay` route, and the widget link generator emits `/overlay?ref=...#token` with the capability only in the fragment (`apps/api/src/domain/overlay-widget-service.mjs:41`). Since OPS-15 cutover Wave 3 ([record](../stories/OPS-15/cutover-wave-3.md)) the legacy `/overlay.html` alias and the vanilla overlay files are gone: no development or production rule rewrites `/overlay.html` (`apps/frontend/scripts/dev-proxy-config.mjs:19-28,39-48`, where `afterFiles` is empty), and `/overlay.html`, `/overlay.js` and `/overlay.css` get a Next 404 without redirect (`tests/integration/compose-runtime.test.js:376`). An OBS source still configured with an older `/overlay.html` link needs a newly generated link. Since OPS-15 cutover Wave 1 (2026-10-27, [record](../stories/OPS-15/cutover-wave-1.md)), production `/` is the Next panel Overview (`apps/frontend/app/(panel)/page.jsx:8`) and Fastify serves no browser file: the only production rewrites to Fastify are `/api/*`, `/overlay/api/*`, `/health` and `/callback` (`apps/frontend/scripts/dev-proxy-config.mjs:41-46`), `apps/api/src/server.mjs` registers no static route, and `/app.js`, `/styles.css`, `/index.html` and `/shared/panel/*` get a Next 404 (`tests/integration/compose-runtime.test.js:372`). The remaining `apps/web/` files (vanilla panel and localization catalogs) stay on disk but are not served; the catalogs move out in cutover Wave 2 and the vanilla panel is removed in Wave 4. `legacy` is historical reference only, never a fallback or rollback target. The panel and overlay have separate route/layout/bundle entries; OBS must not load the panel bundle. The browser never imports Prisma or communicates with Twitch directly. The development API binds to loopback. If `DATABASE_URL` is empty, the launcher starts its separate development PostgreSQL service, snapshots before migrations, and leaves product Compose services and volumes untouched.

The exact overlay URL and authorization contract are an open architecture gate: OPS-13/#57 proposes a capability-free local projection addressed by widget ID, while existing OPS-13 criteria preserve the token capability flow. Resolve this conflict with `$aiox-architect` before migrating or cutting over the overlay. Keep #57 open until native OBS/CEF acceptance.

First-party TSV catalogs remain in the product image. Complete community catalogs live under host `.local/community-catalogs`, mounted into `/app/.local/community-catalogs` read-only with a distinct Compose bind; catalog discovery validates and merges both roots for panel, setup, chat and overlay. The overlay's current catalog cache has a five-second TTL. See [OPS-15](../stories/OPS-15/story.md) for the staged migration and evidence gates.

The local `GET /health` response may include nullable `last_reconciliation_at`, derived from the current Twitch integration process memory. It is not persisted and resets to null on API restart until the next completed reconciliation.

For host development, the API writes the product-locale bootstrap projection under `.local/dev/product-locale.state`; the launcher honors an explicitly configured `PRODUCT_LOCALE_PROJECTION_FILE`. This keeps the development projection in the worktree instead of using the container-only `/app/.local` default.
