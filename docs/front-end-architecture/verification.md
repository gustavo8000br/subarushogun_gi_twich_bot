# Verification
[Português brasileiro](../pt-BR/front-end-architecture/verification.md)


The OPS-15 migration matrix maps every screen/action, API endpoint, locale/catalog dependency, state and test ID before the legacy frontend is removed. The Next dev proxy must be limited to a validated loopback origin, trust the generated local CA when available, and remain absent from production configuration. Verify the production rewrite list (API, overlay API, health and callback to the loopback HTTPS Fastify origin, and nothing else), direct refresh of each Next route, that no rewrite sends `/`, `/app.js` or `/styles.css` to Fastify (removed in cutover Wave 1), and that no development or production rule rewrites or redirects `/overlay.html`, which gets a Next 404 (alias removed in cutover Wave 3; `tests/unit/next-dev-proxy.test.js:56-61`, `tests/integration/compose-runtime.test.js:372-383`). Package and test the `.local/community-catalogs` read-only mount in each unified installer; add a complete locale after image build and prove panel/setup/chat discovery on the next lookup and overlay discovery within the five-second cache TTL. Tests also cover same-origin security contracts, panel/overlay bundle separation, localized form and operation states, and existing keyboard, focus, contrast and FND-7 editor WCAG AA criteria. Keep Host/Origin, session, CSRF, authorization, privacy projection and mutation correctness under backend route/integration tests.

Next panel foundation contracts verify session initialization before protected reads, safe same-origin API errors, CSRF/idempotency headers on writes, expected-revision locale updates, runtime catalog normalization, and use of the protected operator `GET /api/queues` projection. Invalid queue projections must fail visibly instead of becoming a zero-count summary. The first-party pt-BR server-render fallback does not replace runtime catalog discovery or persisted locale reads.

Overlay browser tests open the exact widget link `/overlay?ref=...#token`, check that the retired `/overlay.html` alias gets a 404 without redirect (`tests/e2e/overlay-browser-only.mjs:47-52`), and cover fragment removal, per-ref `sessionStorage`, bearer capability without panel session, 401/403/404 clearing, stale projection retention, unload/reload and revoke/rotate. Performance evidence retains FND-7's target of eight sources and ten updates within two seconds. Validate the Next production server and Fastify together in isolated Compose with disposable PostgreSQL. Native OBS/CEF evidence must identify the tested platform and versions; do not claim unrun checks.

Contracts cover the Next runtime configuration, route files, the absence of any `/overlay.html` rewrite (`tests/unit/next-runtime-config.test.js:38`, `tests/unit/api-static-surface-contract.test.js:41-52`), the widget link format `/overlay?ref=...#token` (`tests/unit/overlay-widget-service.test.js:19-22`), route-specific client bundles, and Fastify callback/API/health precedence. The dedicated Next overlay mounts the existing renderer, and the Docker frontend build copies `apps/shared` and, from `apps/web`, only the localization catalogs (`Dockerfile:9-10`). Production `/` is answered by Next, never by Fastify (`tests/integration/compose-runtime.test.js:372`). Development command contracts verify that `npm run dev` configures separate API/frontend ports, loopback API binding, TLS paths, the same-origin proxy, and a required explicit database URL; a disposable PostgreSQL runtime check remains required before claiming live combined startup. The OPS-13/#57 authorization/URL conflict remains open; this increment preserves the current capability contract and does not decide that conflict.
