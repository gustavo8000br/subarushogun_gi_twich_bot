### Code review

- Cleanup always runs: the `containerStarted` guard and the bare `docker stop` are gone from all 7 files; `afterAll` awaits `cleanupIsolatedPostgres()` with an explicit timeout (105 s = 60 s deadline + one 15 s call + 30 s margin). Vitest runs `afterAll` even when `beforeAll` fails (verified source cited in the research note), so a `Created` orphan is now removed.
- Pull outside `docker run`: `ensurePostgresImage()` inspects first, pulls only on "no such image", fails clearly on any other inspect error (e.g. daemon down) and on pull failure/timeout; every `docker run` uses `--pull never`, so the 30 s `docker run` budget can no longer include a download. Proven above with the image absent, twice.
- No secret leak: `describeDockerResult()` reports status, signal, `error.code` and at most 500 chars of stderr, never stdout (the `inspect` output carries the container env with the test password). The pre-existing `docker logs`/Prisma output in the migration-failure messages of `overlay-widget-repository` and `qra-postgres-fixtures` was not changed by this delta and contains no password.
- Timeouts coherent: `beforeAll` 750 s = 30 s inspect + 600 s pull + previous 120 s setup; cleanup bounded by its deadline plus one in-flight call; unit tests cover each branch (11 cleanup, 5 image) with injected `runDocker`/`sleep`/`now`, no Docker.
- Deviations from the research note, all accepted: (1) 600 s pull / 750 s `beforeAll` instead of 300/420: safer on a slow link; cost is that a hung pull surfaces only after 10 min, bounded and with a clear message. (2) 15 s per cleanup call instead of 30: keeps the `afterAll` budget below 2 min; a slow `rm` becomes `ETIMEDOUT`, which is treated as transient and verified by polling. (3) `volume rm` retried on any failure except "no such volume": broader than "in use", but bounded by the same deadline and reported with stderr. (4) `rm -f` reissued only after a non-transient failure: matches the note. (5) No stdout in messages: stricter than the note, a security improvement. (6) Label `queuebot.test=disposable`: the note's optional suggestion, now used for the leftover check above. (7) `rm -f` instead of `docker stop` in the tmpfs files: idempotent and verified; the database is disposable, so no graceful shutdown is needed. (8) Synchronous `ensurePostgresImage()`: blocks only its own worker inside `beforeAll`, which awaits it anyway.
- Low observations (non-blocking, no change requested now): (a) parallel workers can issue more than one `docker pull` (two seen); the daemon deduplicated the download, but a later integration `globalSetup` (note Q1) would make it one call. (b) After a timed-out `rm -f` the command is not reissued; if the daemon ever dropped the request, cleanup fails visibly at 60 s instead of retrying, which is acceptable for a test helper.
