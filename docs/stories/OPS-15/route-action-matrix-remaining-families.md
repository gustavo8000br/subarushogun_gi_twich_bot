Author: `@dev` (Dex), model Sonnet 5.5. Companion of [queue-route-action-inventory.md](queue-route-action-inventory.md) (23 queue routes, QRA-01..23). This file covers every non-queue route registered in `apps/api/src` (session, health, state, setup, OAuth, reconciliation, localization, commands, operations, account, widgets, overlay). It is built from the route handlers and from a search for each path in `tests/`. **No acceptance is credited here; `@qa` decides.**

The A column is credited ONLY for a test that drives the Fastify route (real `inject`) over the real PostgreSQL repository. A test that exercises only the PostgreSQL repository is labelled **R (repository only, not the route)** and is not A. Route DTO tests that use real Fastify with an injected fake repository or integration are listed in U (they prove the response contract, not persistence). Layers: **U** unit; **A** real Fastify and/or disposable PostgreSQL; **B** real Chrome with INTERCEPTED API (proves the panel behavior, never the API); **C** real Compose stack (Next + Fastify + PostgreSQL) driven by Chromium; **O** native OBS/CEF; **TW** real Twitch. `—` means no test found by the search, not "impossible". Test names are files under `tests/`.

## What the new rows rely on

- Browser scripts (B) use `tests/e2e/fixtures/panel-browser-harness.mjs`, which serves the REAL `en` and `pt-BR` panel TSV catalogs and intercepts only same-origin `/api` and `/health`; cross-origin requests are aborted and recorded, never followed. Each script prints its boundary.
- The new browser scripts found one real defect: `panel.command.conflict` was used by `/commands` on a 409 but absent from the `en`, `es` and `pt-BR` catalogs (only a unit test injected it). The key was added to the three catalogs.
- FT-06 package 2026-11-15 added `unit/panel-route-dto-contract.test.js` (route DTO contract, class U), `integration/panel-account-route-postgres.test.js` (class A, PostgreSQL) and `e2e/route-parity-browser-only.mjs` (class FX: fixtures, never PG or TW). The four `DEFECT` tests (formerly `it.fails`) now run as normal tests, because the defects were fixed on 2026-11-15.
- Defects found and FIXED on 2026-11-15 (awaiting the `@qa` gate): the account routes and `/api/state` now return only `{label, source, defaultLabel}` through one `accountDto` projection (the repository still stores `updatedBy` for audit); ACC-01 and ACC-02 unexpected failures are a 500 generic body with `referenceId` (invalid labels stay 400); the overlay `sendError` reports a safe diagnostic and returns `referenceId` on the 503 (409/404/400 unchanged). Original findings: (1) ACC-01/ACC-02/STA-01 return the raw stored account state, including `updatedBy` (the HttpOnly local session id) and `ownerEntryId` (`apps/api/src/http/queue-routes.mjs`, `/api/state` `account`, `/api/account` and `/api/account/default` handlers; `apps/api/src/persistence/queue-repository.mjs`, `setCurrentAccount` and `setDefaultAccountLabel` return `next`); (2) ACC-01 unexpected 500 has no `referenceId`; (3) ACC-02 maps any repository failure to 400; (4) the overlay `sendError` (WID-03/06, shared by all widget management routes) answers 503 without `referenceId` and without a diagnostic.
- Still not covered (open gaps to carry): REC-01 in a browser; SET-01..04, CMD-02, ACC-01/02 and WID-03/06 in a real stack (class C); the `/connection` disconnect flow does not exist in the panel, so none was tested.
