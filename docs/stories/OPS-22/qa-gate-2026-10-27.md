## Code review

- **Sensitive data:** no `error.message` is logged or stored (Twurple puts URL and body in it, `HttpStatusCodeError.js:12`); Twurple's error has no `code`, so `errorCode()` falls back to fixed codes. `queueId`/`redemptionId` stay only in the status object and the `POST /api/reconciliation` response (pre-existing) and never reach the log. Logging failures are swallowed and cannot change reconciliation.
- **Patterns:** small pure module, JSDoc, allowlist logger, dependency injection of `logEvent` with a no-op default. `@twurple/common` 8.2.0 (direct) and `@twurple/api-call` 8.2.0 (dev) pinned in lockstep; the lockfile diff is 2 lines (both were already installed transitively).
- **Tests with real Twurple instances:** a single helper calls the `@private` constructors; synthetic fixture data only (no real channel/viewer).

## Answers to the `@dev` questions

1. **Real 403 now becomes `failed` (was retry):** acceptable. It aligns the real Twurple error with the behavior already designed for `{ status: 403 }` (`isPermanentHttpFailure`) and with `@architect` §2 (403 permanent: Client-ID mismatch or ineligible channel will not heal by waiting). `failed` is visible in Operations and can be retried manually; it never confirms anything. Only the reason code differs from the architect's name (C-3).
2. **Additive `httpStatus` on reconciliation issues, including `POST /api/reconciliation`:** acceptable. OPS-21 governs non-2xx `code` and mutation idempotency, not this 2xx body; both panels only use `Array.isArray(result.issues)` and `issues.length` (`apps/web/app.js:892`, `operations-page-content.jsx:174-187`, `connection-page-content.jsx:92`). The field is an integer only, with no message/body/header, and the full suite stays green. Record it in the endpoint inventory (INV-07) when OPS-21 publishes the response shapes.
3. **Story left Ready without InProgress:** process deviation (story-lifecycle: `@dev` moves Ready → InProgress at start). Recommendation: `@dev` (or `@po`) records `Ready → InProgress` in the OPS-22 Change Log (en/pt-BR) dated 2026-10-27 with "slice 1 FT-24 delivered, slices 2-3 pending".
