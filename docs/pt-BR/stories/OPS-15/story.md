## História

Como streamer que opera o bot localmente,
quero que todas as interfaces do navegador sejam organizadas em um frontend modular Next.js,
para que o painel e o overlay possam evoluir com limites claros entre funcionalidades e componentes, preservando o comportamento atual e a segurança local.

## Escopo e decisões

- Refatorar todos os fluxos atuais do painel acessíveis pelo navegador e o renderer do overlay OBS. A migração será feita por superfícies visíveis; não é um protótipo parcial do painel.
- Usar Next.js App Router com servidor Node de produção sobre a porta HTTPS local existente. Fastify continua autoridade de domínio, persistência, integrações e API, escutando somente no loopback do contêiner. Next encaminha `/api/*`, `/overlay/api/*`, `/health` e `/callback` para Fastify por HTTPS local confiável. Mantenha a porta pública local existente; não adicione portas públicas nem transfira comportamento de API/domínio para handlers do Next.
- Em desenvolvimento, a origem do documento do overlay é o Next dev HTTPS em loopback (`NEXT_DEV_PORT`); seu proxy same-origin de API aponta para Fastify. Em produção, o documento do overlay é servido pelo Next na porta `3000` do contêiner, mapeada para a `APP_PORT` pública existente no host; chamadas de API são encaminhadas ao Fastify privado em `API_PORT`. Gere URLs de capability do widget a partir de `PUBLIC_BASE_URL` (origem pública Next). Faça bind local do Next em loopback durante desenvolvimento; no Compose, use a interface do contêiner, mantendo a publicação no host limitada a loopback.
- O Next roda com `trailingSlash: false` (`apps/frontend/scripts/next-runtime-config.mjs:10`): rotas canônicas do painel não têm barra final (`/queues`). O servidor Next de produção atende em runtime a rota do overlay, `/overlay` (sem barra final; responde 200 sem redirecionamento), que é a URL do overlay servida pelo painel Next; teste essa URL com query/fragmento e os assets `/_next/` servidos pela origem Next. O caminho literal legado `/overlay.html` e seus aliases (o rewrite do Next e o redirect de desenvolvimento do Fastify) foram removidos na Onda 3 do cutover ([`cutover-wave-3.md`](cutover-wave-3.md)): não há usuários ativos até o `rc` (OW-09, proprietário, 2026-10-27), e `/overlay.html` agora recebe o 404 do Next. *(A redação anterior "mantenha `trailingSlash: true`", "hoje `/overlay/`" e "hoje reescrito para essa rota; pode ser removido na Onda 3" foi superada pela decisão de 2026-10-27 / Onda 3; registro histórico.)*
- Preservar a URL do overlay servida pelo painel Next (`?ref=...#token`) e a semântica atual da capability OBS. Aliases antigos (`/overlay.html` e links de desenvolvimento emitidos na origem da API pelo redirect temporário do Fastify para Next) não são obrigatórios (sem usuários ativos até o `rc`); enquanto esse redirect existir, ele não pode levar o segredo do fragmento no `Location`. O servidor HTTPS Next de produção atende o documento; o renderer no navegador mantém leituras `/overlay/api/widget` sem cache a cada segundo, para refletir alterações de conta/fila e revogação da capability. A rota do overlay nunca deve cair no documento do overlay do Fastify.
- Manter a lógica do callback OAuth em rota dinâmica explícita do Fastify e encaminhar `/callback` por Next. Desde a Onda 1 do cutover (2026-10-27, FT-38), o Fastify não serve root estático nem página web: o Next responde `/` e todos os demais caminhos que não são de API, e os assets vanilla legados (`/app.js`, `/styles.css`, `/index.html`, `/shared/*`) recebem o 404 do Next, nunca conteúdo do Fastify. *(O encaminhamento transitório anterior de caminhos legados do painel ao root estático do Fastify foi superado pela decisão de 2026-10-27; registro histórico.)* Next é dono do documento do overlay e de seus assets `/_next/*`; Fastify permanece privado e não pode ser acessado diretamente pelo host.
- Direção do proprietário (2026-10-15): como painel/OBS devem ficar neste computador em `127.0.0.1`, avaliar remover a capability bearer da URL do overlay. Manter a proteção CSRF do painel nas mutações. A API atual do overlay ainda usa capability; resolver o conflito arquitetural OPS-13/#57 e verificar os limites de segurança loopback antes de alterar esse contrato.
- Usar a estrutura feature-first revisada: `app/`, `features/`, `components/ui/`, `lib/api/`, `lib/i18n/` e `styles/`. Manter o código do navegador em JavaScript ESM com JSDoc para preservar o requisito atual do produto. O pipeline necessário de build, transpilation e bundling do Next é a exceção documentada à restrição atual sem bundler; isso não implica adotar TypeScript.
- Manter `/api/localization/catalogs` como fonte runtime dos bundles validados, incluindo catálogos comunitários completos instalados depois do build da imagem frontend. Usar os catálogos first-party da imagem e um diretório separado `.local/community-catalogs`, gerenciado no host e montado como somente leitura no bot (`${LOCAL_COMMUNITY_CATALOG_DIRECTORY:-./.local/community-catalogs}` -> `/app/.local/community-catalogs`, sintaxe longa Compose com `type: bind`, `read_only: true` e `bind.create_host_path: false`); combinar e validar as duas raízes para consumidores do painel, setup, chat e overlay. Os instaladores unificados criam o diretório, e o Compose empacotado deve manter o mount. Painel/setup/chat observam o catálogo na próxima consulta; o cache atual de catálogos do overlay pode atrasar a observação em até cinco segundos. Ler e atualizar o idioma persistido pela API local existente. Não substituir a descoberta runtime por bundles somente de build ou i18n por rotas Next.
- Seguir a direção visual existente em [pesquisa UX FND-6](../FND-6/ux-research.md), [pesquisa UX OPS-6](../OPS-6/ux-research.md) e [refinamento UX FND-7](../FND-7/ux-refinement.md): superfícies locais escuras, ações/foco roxos moderados, fontes do sistema, rótulos operacionais legíveis, padrões reutilizáveis de controle/estado e a prévia estabelecida do editor de overlay. Não introduzir fontes, scripts, imagens ou telemetria externos.
- Esta é uma migração de apresentação/build. Não adiciona regras de domínio e não altera semântica da API backend, autorização, operações Twitch, ciclo de vida de filas, comportamento financeiro/outbox ou schema do banco.
- A branch `legacy` é uma branch remota real e protegida (`a9279b2`, ruleset `legacy-no-delete-no-force-push`), mantida apenas como referência histórica: não é fallback de runtime, não é alvo de rollback e nunca é reimplantada. O painel vanilla é descontinuado de forma incremental, onda por onda, conforme o [`cutover-plan.md`](cutover-plan.md); o rollback de qualquer onda = reverter o commit dessa onda. Não é exigido ensaio de rollback a partir da `legacy` (decisões do proprietário de 2026-10-21 e 2026-10-27).

## Contratos existentes a preservar

- Next é o único servidor público de documentos após esta fatia do overlay; o Compose publica a única porta do produto somente em loopback. Fastify é servidor HTTPS interno de API/domínio, preservando os caminhos same-origin existentes de sessão e API.
- `apps/api/src/http/local-session.mjs` continua autoritativo para validação de Host/Origin, cookie de sessão, inicialização de sessão API e proteção CSRF. O launcher local de desenvolvimento no Windows pode permitir somente a origem exata configurada do Next (padrão `https://localhost:<NEXT_DEV_PORT>`); deve validar Host e Origin contra essa origem exata e rejeitar outros hosts, esquemas, portas ou origens. Produção permanece localhost-only e não pode herdar allowlists de desenvolvimento. Mutations mantêm chaves de idempotência, revisões esperadas, autorização de rota e schemas de requisição atuais.
- A interface consome projeções de API allowlisted. Não importa Prisma, duplica transições de domínio, contata Twitch diretamente nem expõe exceções brutas, segredos, tokens, UIDs fora da política atual de privacidade ou HTML não confiável.
- As atualizações em tempo real do painel usam Server-Sent Events (SSE), entregues pela OPS-23 (decisão do proprietário de 2026-10-27); o polling de 5 s / 2 s fica apenas como fallback da OPS-23 quando o fluxo estiver indisponível, e não como contrato desta story. A preservação de foco/contexto durante as atualizações continua valendo. Esta story não introduz WebSocket para o painel.
- A URL do overlay servida pelo painel Next, as referências de capability e o tratamento do segredo em fragmento continuam compatíveis; caminhos da API do overlay, revogação, reload e projeção da conta atual continuam funcionando no OBS/CEF. Aliases antigos da URL do overlay (inclusive `/overlay.html`) não são obrigatórios: não há usuários ativos até o `rc` (OW-09, proprietário, 2026-10-27).

`last_reconciliation_at` é um timestamp ISO anulável, mantido na memória runtime da integração Twitch; o rótulo identifica que o valor pertence à execução atual da API e, após reiniciar, permanece nulo até a próxima conciliação concluída. `pending_operations` contém detalhes recentes; o resumo exato agrupa no PostgreSQL os estados não resolvidos de todos os registros outbox elegíveis, portanto o limite do histórico de 200 itens não oculta pendências antigas. Registros confirmados, resolvidos manualmente ou cancelados não aumentam a contagem. Uma atualização com falha, inclusive quando somente a leitura de saúde falhar, preserva o snapshot válido anterior e mostra um aviso localizado de dados possivelmente desatualizados.

## Critérios de aceite

1. **Migração integral e paridade:** Todas as superfícies, ações e estados da matriz estão implementados no novo frontend. Cada linha aponta para testes identificados e um registro de paridade executado. Nenhuma tela ou comportamento de overlay legado é omitido silenciosamente. `$aiox-ux-design-expert` confirma que o inventário visual/de interação revisado está representado; essa revisão não substitui QA.

2. **Estrutura feature-oriented:** O código segue os limites revisados em `app/`, `features/`, `components/ui/`, `lib/api/`, `lib/i18n/` e `styles/`. Composição de rotas/layouts fica separada do comportamento de features; lógica de API, localização e UI compartilhada não é duplicada por página. Código do navegador permanece JavaScript ESM com JSDoc; módulos JSX usam configuração explícita de `jsx` no typecheck TypeScript e parser JSX no ESLint. Esta story não introduz código de aplicação TypeScript.

3. **Overlay dinâmico servido pelo Next e propriedade exata das rotas:** O servidor Node Next de produção entrega a URL do overlay servida pelo painel Next (`?ref=...#token`, rota isolada do overlay `/overlay`, sem barra final, 200 sem redirecionamento) pela porta HTTPS existente. Aliases antigos (inclusive o rewrite de `/overlay.html`) foram removidos na Onda 3 do cutover ([`cutover-wave-3.md`](cutover-wave-3.md)); `/overlay.html` recebe o 404 do Next: não há usuários ativos até o `rc` (OW-09, proprietário, 2026-10-27). *(A redação anterior "hoje `/overlay/`" e "não são obrigatórios" foi superada pela decisão de 2026-10-27 / Onda 3.)* O renderer no navegador consulta `/overlay/api/widget` sem cache a cada segundo, preservando atualizações de conta/fila, recuperação de status e revogação da capability. Next encaminha `/overlay/api/*`, `/api/*`, `/health` e `/callback` ao Fastify por HTTPS privado confiável. Desde a Onda 1 do cutover (2026-10-27, FT-38), o Fastify não serve root estático nem página web: o Next responde `/` e todos os demais caminhos que não são de API, e os assets vanilla legados (`/app.js`, `/styles.css`, `/index.html`, `/shared/*`) recebem o 404 do Next, nunca conteúdo do Fastify. *(O encaminhamento transitório anterior ao root estático do Fastify foi superado pela decisão de 2026-10-27; veja [`cutover-wave-1.md`](cutover-wave-1.md).)* O contêiner publica no host somente o listener Next em loopback; Fastify escuta em loopback interno. Rotas API inexistentes não podem retornar HTML do painel. Validar build, inicialização, refresh direto e propriedade das rotas em Compose descartável com PostgreSQL. Não há deploy público, porta adicional no host nem API cross-origin de produção.

4. **Entradas e bundles separados:** Painel e overlay têm layouts e bundles de navegador separados. Uma verificação do manifesto/build de produção prova que carregar a URL do overlay servida pelo painel Next (`/overlay`, canônica com `trailingSlash: false`) não carrega o bundle da aplicação do painel. *(Este CA citava o caminho exato `/overlay.html` até 2026-10-27 e, depois, "canônica `/overlay/` com `trailingSlash: true`"; ambos superados pela decisão de 2026-10-27, OW-09: o alias foi removido na Onda 3 do cutover.)* O bundle do overlay inclui apenas módulos necessários à renderização OBS e seu contrato de API existente.

5. **Paridade da localização runtime:** O painel carrega `/api/localization/catalogs` em runtime e aceita o conjunto de locales validado pelo Fastify. O backend combina catálogos first-party da imagem com catálogos comunitários completos em `.local/community-catalogs`, montados read-only e instalados depois do build; painel, setup, chat e overlay descobrem a nova locale sem rebuild nem reinício da API. A descoberta pelo overlay fica visível em até cinco segundos, conforme TTL de cache atual. Catálogos comunitários são validados contra chaves/placeholders first-party; arquivos inválidos ou colisões não substituem conteúdo first-party válido. O Compose gerado por cada um dos três instaladores mantém esse mount e o diretório existe no host. O idioma persistido é lido/alterado pela API protegida e respeita conflitos de revisão. Chaves/placeholders/plurais de inglês, espanhol e pt-BR são completos e seguros; texto estático não substitui cópia de produto pertencente a catálogos por literais não localizados.

6. **Paridade de segurança/API:** Política de produção para Host/Origin, HTTPS, cookie e inicialização de sessão local, CSRF, autorização, idempotência e revisões esperadas permanece inalterada e coberta por testes de regressão. O launcher local multiplataforma permite somente a origem Next exata configurada para inicialização de sessão; chamadas pelo proxy same-origin devem carregar Host/protocolo encaminhados correspondentes e origens inesperadas continuam rejeitadas. Testes cobrem origem configurada aceita e host, esquema, porta e origem rejeitados, além de provar que produção não herda a allowlist de desenvolvimento. O navegador usa somente chamadas same-origin e projeções explícitas da API. Não chama Twitch, importa Prisma, enfraquece filtragem de UID, persiste credenciais em estado/storage frontend, expõe segredos, renderiza HTML não confiável nem apresenta exceções brutas.

7. **Paridade visual e de comportamento do produto:** Semântica de atualização em tempo real (SSE entregue pela OPS-23 como dependência do cutover, com o polling de 5 s / 2 s apenas como fallback dela; sem WebSocket no painel), fluxos de usuário, estado remoto pendente-versus-confirmado, preservação de foco, etapas de confirmação destrutiva, salvar permissões, atualizações de fila/conta, recuperação de operação e widgets continuam conforme os contratos backend aprovados. Aliases antigos (inclusive `/overlay.html`) não são obrigatórios e foram removidos na Onda 3 do cutover: não há usuários ativos até o `rc` (OW-09, proprietário, 2026-10-27). Testes cobrem remoção do fragmento, `sessionStorage` por ref, uso de bearer capability sem sessão do painel, limpeza em 401/403/404, retenção de projeção obsoleta, unload/reload, revogação/rotação, sete tipos de fonte suportados em oito fontes simultâneas e dez mudanças dentro do orçamento FND-7 existente de 2 segundos. Preservar atualização da conta atual, fallback e widgets suportados. Registrar plataforma e versões OBS/CEF. Não alegar runtime nativo não executado; aceite pendente impede concluir a story.

9. **Cutover incremental por ondas e rollback:** O painel vanilla é cortado de forma incremental, em ondas pequenas e reversíveis definidas no [`cutover-plan.md`](cutover-plan.md), uma onda por vez (primeiro a Onda 0, código morto; depois a Onda 1, `/` para o Next). ### FT-21 — D-1: confirmação de `!<fila> limpar CONFIRMAR` em qualquer caixa ou idioma (issue #89, P1, tamanho P)

Fonte: LB-35. Sem gate de banco e sem gate de UX (nenhum texto visível novo).

1. **Dado** `limpar` (ou `clear`) seguido do rótulo de confirmação localizado em qualquer caixa ou acento (`CONFIRMAR`, `Confirmar`, `confirmár`; em `en`, `confirm`), **quando** o comando é tratado, **então** `clearConfirmation.confirm` é chamado exatamente uma vez.
2. **Dado** o rótulo em minúsculas que funciona hoje, **quando** o comando é tratado, **então** continua funcionando (sem regressão).
3. **Dado** qualquer outra palavra após `limpar`/`clear`, **quando** o comando é tratado, **então** o resultado segue `INVALID_SYNTAX` e nada é limpo.
4. **Dado** que o handler decide sobre a confirmação, **quando** o código é lido, **então** ele usa o resultado do parser (`confirm: true` ou `args.length === 1`) e nunca uma comparação literal de texto (causa em `chat-handler.mjs:266`).
5. **Evidência:** testes Red do parser e do handler primeiro; depois a correção; gate do `@qa`.

### FT-22 — D-2: posição na chamada (`(posição ?)`) via `previousPosition` no payload do outbox (issue #90, P1, tamanho P)

Fonte: LB-29 (esperado `1`). Gate: **confirmação escrita do `@data-engineer`** de que o JSON de `outbox.payload` comporta `{ previousPosition }` sem DDL (o `@architect` espera que não haja; o `data-review.md` da OPS-22 informa que não há migration para as tarefas financeiras, mas não cobre este campo). O `@dev` só começa após essa confirmação.

1. **Dado** uma entrada em espera chamada na posição N pelo painel ou pelo chat, **quando** a chamada é enfileirada, **então** `{ previousPosition: N }` é gravado no `payload` do outbox e o aviso mostra `posição N` (LB-29 esperava `1`).
2. **Dado** que o worker envia o aviso, **quando** ele lê a posição, **então** lê o valor da tarefa reivindicada, não `entry.callPosition`.
3. **Dado** uma linha antiga do outbox com `payload: {}`, **quando** o worker envia o aviso, **então** recorre à consulta de auditoria de `previousPosition`.
4. **Evidência:** teste unitário do worker (Red primeiro) mais teste de integração em PostgreSQL isolado com migrations reais (nunca SQLite nem mocks do Prisma).

### Referências técnicas externas verificadas em 2026-10-19

- O Next.js documenta que static export produz arquivos estáticos e não oferece recursos que dependam do runtime Next. Mantenha API/sessão/OAuth runtime no Fastify e verifique rotas/assets gerados. [Guia Next.js de SPA/static export](https://nextjs.org/docs/app/guides/single-page-applications).
- A documentação do OBS descreve Browser Source como fonte de página web/arquivo local baseada no Chromium Embedded Framework. Portanto, o gate final de compatibilidade deve executar no OBS/CEF nativo e registrar versões; Chromium comum não é evidência equivalente. [Documentação OBS Browser Source](https://obsproject.com/kb/browser-source), [documentação CEF](https://chromiumembedded.github.io/cef/).
- Para o pré-requisito de banco local Windows bloqueado, o Docker Desktop documenta o backend WSL 2 e os requisitos de instalação; PostgreSQL nativo no Windows é uma opção separada somente para desenvolvimento quando `DATABASE_URL` aponta para banco isolado. Escolha um caminho e registre versão/alvo exatos; nenhum dos caminhos comprova comportamento do instalador de produto ou Compose. [Docker Desktop no Windows](https://docs.docker.com/desktop/setup/install/windows-install/), [backend WSL do Docker Desktop](https://docs.docker.com/desktop/features/wsl/), [downloads PostgreSQL para Windows](https://www.postgresql.org/download/windows/), [Prisma Migrate](https://www.prisma.io/docs/orm/prisma-migrate).
- Essas fontes confirmam somente restrições técnicas; não comprovam paridade do projeto, aceite de segurança, instalação bem-sucedida nem evidência de runtime nativo.
