## História

Como streamer que opera o bot localmente,
quero que todas as interfaces do navegador sejam organizadas em um frontend modular Next.js,
para que o painel e o overlay possam evoluir com limites claros entre funcionalidades e componentes, preservando o comportamento atual e a segurança local.

## Escopo e decisões

- Refatorar todos os fluxos atuais do painel acessíveis pelo navegador e o renderer do overlay OBS. A migração será feita por superfícies visíveis; não é um protótipo parcial do painel.
- Usar Next.js App Router com `output: 'export'`. Fastify continua sendo o servidor HTTPS local e serve os assets estáticos exportados na mesma origem da API existente. Não adicionar servidor Next em produção, hospedagem pública, nova porta pública de produção nem proxy de API em produção. O comando de desenvolvimento pode iniciar Fastify e Next juntos e usar um proxy loopback exclusivo de desenvolvimento.
- Configurar `trailingSlash: true`: rotas do painel usam URLs canônicas com barra (`/queues/`) e exportam para `out/queues/index.html`, servidas pelo Fastify com tratamento de `index.html`. A página App Router `/overlay/` exporta para `out/overlay/index.html`; o build estático copia esse documento para o artefato literal `out/overlay.html`. Fastify serve esse arquivo exato para `/overlay.html?ref=...#token`; não há redirect, rewrite de URL nem fallback SPA. Testar as URLs dos assets gerados nos documentos aninhados do painel e no alias do overlay.
- Preservar exatamente a URL preexistente `GET /overlay.html?ref=...#token` e o contrato atual de capabilities OBS. Painel e overlay terão entradas/layouts/bundles separados; o overlay não deve baixar o bundle da aplicação do painel.
- Manter o callback OAuth dinâmico como rota explícita do Fastify. O frontend estático não deve interceptar `/callback`, `/api/*`, `/health` ou `/overlay/api/*`.
- Direção do proprietário (2026-10-15): como painel/OBS devem ficar neste computador em `127.0.0.1`, avaliar remover a capability bearer da URL do overlay. Manter a proteção CSRF do painel nas mutações. A API atual do overlay ainda usa capability; resolver o conflito arquitetural OPS-13/#57 e verificar os limites de segurança loopback antes de alterar esse contrato.
- Usar a estrutura feature-first revisada: `app/`, `features/`, `components/ui/`, `lib/api/`, `lib/i18n/` e `styles/`. Manter o código do navegador em JavaScript ESM com JSDoc para preservar o requisito atual do produto. O pipeline necessário de build, transpilation e bundling do Next é a exceção documentada à restrição atual sem bundler; isso não implica adotar TypeScript.
- Manter `/api/localization/catalogs` como fonte runtime dos bundles validados, incluindo catálogos comunitários completos instalados depois do build da imagem frontend. Usar os catálogos first-party da imagem e um diretório separado `.local/community-catalogs`, gerenciado no host e montado como somente leitura no bot (`${LOCAL_COMMUNITY_CATALOG_DIRECTORY:-./.local/community-catalogs}` -> `/app/.local/community-catalogs`, sintaxe longa Compose com `type: bind`, `read_only: true` e `bind.create_host_path: false`); combinar e validar as duas raízes para consumidores do painel, setup, chat e overlay. Os instaladores unificados criam o diretório, e o Compose empacotado deve manter o mount. Painel/setup/chat observam o catálogo na próxima consulta; o cache atual de catálogos do overlay pode atrasar a observação em até cinco segundos. Ler e atualizar o idioma persistido pela API local existente. Não substituir a descoberta runtime por bundles somente de build ou i18n por rotas Next.
- Seguir a direção visual existente em [pesquisa UX FND-6](../FND-6/ux-research.md), [pesquisa UX OPS-6](../OPS-6/ux-research.md) e [refinamento UX FND-7](../FND-7/ux-refinement.md): superfícies locais escuras, ações/foco roxos moderados, fontes do sistema, rótulos operacionais legíveis, padrões reutilizáveis de controle/estado e a prévia estabelecida do editor de overlay. Não introduzir fontes, scripts, imagens ou telemetria externos.
- Esta é uma migração de apresentação/build. Não adiciona regras de domínio e não altera semântica da API backend, autorização, operações Twitch, ciclo de vida de filas, comportamento financeiro/outbox ou schema do banco.
- A branch local-only `legacy` já aponta para a baseline `845a58f` e é um ponteiro Git fixo de recuperação, não um fallback de runtime. Esta story não cria uma branch `legacy` remota. Manter o ponteiro local inalterado. Antes do cutover de produção, registrar um ensaio de rollback dessa revisão em um projeto Compose isolado sem tocar volumes ativos do produto.

## Contratos existentes a preservar

- Fastify continua sendo o único servidor HTTP runtime. O Compose continua publicando o produto somente em loopback. A sessão local e os caminhos de API same-origin atuais permanecem.
- `apps/api/src/http/local-session.mjs` continua autoritativo para validação Host/Origin, cookie de sessão, inicialização de sessão API e proteção CSRF. O launcher dev pode permitir somente a origem HTTPS exata do Codespaces para a porta encaminhada do Next; produção e demais origens continuam sob a regra localhost-only. Mutations mantêm chaves de idempotência, revisões esperadas, autorização de rota e schemas de requisição atuais.
- A interface consome projeções de API allowlisted. Não importa Prisma, duplica transições de domínio, contata Twitch diretamente nem expõe exceções brutas, segredos, tokens, UIDs fora da política atual de privacidade ou HTML não confiável.
- O polling limitado existente e o comportamento de preservação de foco/contexto continuam. Esta story não introduz WebSocket para o painel.
- URLs existentes do overlay, referências de capability e tratamento do segredo em fragmento continuam compatíveis. `GET /overlay.html`, caminhos da API do overlay, revogação, reload e projeção da conta atual continuam funcionando no OBS/CEF.

## Critérios de aceite

1. **Migração integral e paridade:** Todas as superfícies, ações e estados da matriz estão implementados no novo frontend. Cada linha aponta para testes identificados e um registro de paridade executado. Nenhuma tela ou comportamento de overlay legado é omitido silenciosamente. `$aiox-ux-design-expert` confirma que o inventário visual/de interação revisado está representado; essa revisão não substitui QA.

2. **Estrutura feature-oriented:** O código segue os limites revisados em `app/`, `features/`, `components/ui/`, `lib/api/`, `lib/i18n/` e `styles/`. Composição de rotas/layouts fica separada do comportamento de features; lógica de API, localização e UI compartilhada não é duplicada por página. Código do navegador permanece JavaScript ESM com JSDoc; módulos JSX usam configuração explícita de `jsx` no typecheck TypeScript e parser JSX no ESLint. Esta story não introduz código de aplicação TypeScript.

3. **Export estático e rotas exatas do servidor:** Um build de produção gera somente assets estáticos com `trailingSlash: true`: cada rota canônica `/x/` do painel gera `out/x/index.html`, e a página `/overlay/` gera `out/overlay/index.html`, copiada no postbuild para `out/overlay.html`. O Fastify serve somente `out/` com `index.html`, `redirect: false` e sem fallback SPA; refresh direto em `/x/` e `GET /overlay.html?ref=...` retornam o HTML correto com 200 e sem `Location`. Os assets referenciados pelo alias são requisitados com sucesso. `/callback`, `/api/*`, `/health` e `/overlay/api/*` chegam aos handlers Fastify existentes; rota API inexistente não retorna fallback HTML. Validar build/serving com PostgreSQL descartável em Compose isolado. Não há processo servidor Next, deploy público, porta pública nova, API cross-origin nem reverse proxy.

4. **Entradas e bundles separados:** Painel e overlay têm layouts e bundles de navegador separados. Uma verificação do manifesto/build de produção prova que carregar `/overlay.html` não carrega o bundle da aplicação do painel. O bundle do overlay inclui apenas módulos necessários à renderização OBS e seu contrato de API existente.

5. **Paridade da localização runtime:** O painel carrega `/api/localization/catalogs` em runtime e aceita o conjunto de locales validado pelo Fastify. O backend combina catálogos first-party da imagem com catálogos comunitários completos em `.local/community-catalogs`, montados read-only e instalados depois do build; painel, setup, chat e overlay descobrem a nova locale sem rebuild nem reinício da API. A descoberta pelo overlay fica visível em até cinco segundos, conforme TTL de cache atual. Catálogos comunitários são validados contra chaves/placeholders first-party; arquivos inválidos ou colisões não substituem conteúdo first-party válido. O Compose gerado por cada um dos três instaladores mantém esse mount e o diretório existe no host. O idioma persistido é lido/alterado pela API protegida e respeita conflitos de revisão. Chaves/placeholders/plurais de inglês, espanhol e pt-BR são completos e seguros; texto estático não substitui cópia de produto pertencente a catálogos por literais não localizados.

6. **Paridade de segurança/API:** Validação Host/Origin, HTTPS, cookie e inicialização de sessão local, CSRF, autorização, idempotência e revisões esperadas permanecem inalterados e cobertos por testes de regressão. O navegador usa somente chamadas same-origin e projeções explícitas da API. Não chama Twitch, importa Prisma, enfraquece filtragem de UID, persiste credenciais em estado/storage frontend, expõe segredos, renderiza HTML não confiável nem apresenta exceções brutas.

7. **Paridade visual e de comportamento do produto:** Polling e semântica atuais, fluxos de usuário, estado remoto pendente-versus-confirmado, preservação de foco, etapas de confirmação destrutiva, salvar permissões, atualizações de fila/conta, recuperação de operação e widgets continuam conforme os contratos backend aprovados. Reutilizar a direção visual documentada em FND-6/OPS-6/FND-7 e preservar o comportamento existente de teclado, foco e contraste. A meta WCAG AA da FND-7 permanece válida para controles e chrome do editor de widgets; não ampliá-la a todas as superfícies do painel nem alterar silenciosamente um estilo de saída do overlay configurado pelo streamer. Nenhuma regra nova de negócio/domínio é introduzida.

8. **Compatibilidade OBS/CEF:** A URL preexistente exata `/overlay.html?ref=...#token` funciona sem redirect/rewrite no E2E browser e em OBS/CEF nativo. Testes cobrem remoção do fragmento, `sessionStorage` por ref, uso de bearer capability sem sessão do painel, limpeza em 401/403/404, retenção de projeção obsoleta, unload/reload, revogação/rotação, oito fontes simultâneas e dez mudanças dentro do orçamento FND-7 existente de 2 segundos. Preservar atualização da conta atual, fallback e widgets suportados. Registrar plataforma e versões OBS/CEF. Não alegar runtime nativo não executado; aceite pendente impede concluir a story.

9. **Rollout incremental seguro e rollback:** Cada fase passa testes focados antes do cutover da próxima superfície. A branch local-only `legacy` permanece fixa em `845a58f` como ponteiro Git de recuperação, não fallback runtime; esta story não inclui branch remota. Antes de remover assets vanilla ou alterar raízes estáticas Docker de produção, ensaiar build de rollback dessa baseline em Compose isolado com os mesmos contratos locais de URL/API, sem tocar volumes ativos DB/segredos. Documentar comandos de cutover/rollback e hashes testados.

10. **TDD e gates do projeto:** Comportamento novo/alterado é testado primeiro; cada fase registra comandos/resultados exatos Red, Green e Refactor. A implementação final passa `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npm run review:static`, `npm run validate:localization`, `npm run validate:version`, `npm run validate:port-denylist`, `docker compose config --quiet` e `git diff --check`; executar também verificações de navegador/OBS da matriz. `$aiox-qa` mapeia todos os AC às evidências e registra score final. Nenhum teste ou score é alegado antes da execução.

11. **Documentação e conclusão da story:** Atualizar arquitetura frontend, restrições de segurança/runtime, índices da story, File List da implementação, evidência TDD e handoff equivalentes em inglês/pt-BR no mesmo incremento. Atualizar README, guia de integração e changelog beta somente quando instruções de operação ou comportamento visível ao usuário mudarem. Não marcar Done enquanto gates de UX/arquitetura/QA ou aceite OBS/CEF obrigatório continuarem pendentes.
12. **Auditoria de testes legados após paridade:** Depois que todas as superfícies Next.js atingirem paridade comportamental, auditar os testes vinculados ao painel vanilla antes do cutover/remoção. Preservar contratos comportamentais; substituir ou remover assertions específicas do markup/implementação legada somente após passar cobertura comportamental equivalente no Next.js. Registrar a decisão e a evidência de cada teste em artefato bilíngue.
13. **Revisão UX antes de criar UI:** Antes de criar uma rota, módulo de feature ou componente compartilhado, registrar e aprovar tarefa do usuário, hierarquia, estados relevantes de carregamento/vazio/erro/pendente/confirmado/desatualizado, comportamento responsivo e por teclado, conteúdo localizado, primitives reutilizáveis e critérios de acessibilidade aplicáveis. A auditoria bilíngue registra o score inicial **6/10** e a revisão no navegador **10/10** para as correções revisadas e estados padrão/vazios em 390×844, 768×900 e 1440×900. Estados preenchidos de fila/configurações e overlay continuam sem revisão no navegador; isso não fecha o gate UX completo da OPS-15.
