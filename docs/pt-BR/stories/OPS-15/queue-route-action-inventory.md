# Rastreabilidade de rotas/ações de fila OPS-15 — primeira fatia detalhada

[English](../../../stories/OPS-15/queue-route-action-inventory.md)

**Status:** Base de rotas/ações inspecionada no código, 2026-10-19. Evidências runtime/browser estão Pendente; este arquivo não declara paridade ou aceite da story.
**Story pai:** [Inventário de endpoints/catálogos OPS-15](endpoint-catalog-inventory.md), In Progress.

## Escopo e regras de evidência

Esta fatia expande as rotas de lista/configuração de filas, atendimento, recuperação de reward e ciclo de vida de INV-05/06. Os contratos foram inspecionados em `apps/api/src/http/queue-routes.mjs`; a existência e execução das assertions estão registradas nas matrizes e no handoff OPS-15 atual. A fronteira de segurança compartilhada QRA-S vale para QRA-01–QRA-23: `local-session.mjs` permite somente o Host local configurado e a Origin de desenvolvimento exata; `/api/*`, exceto `/api/session`, exige sessão local (401), e métodos inseguros, exceto `/callback`, exigem CSRF correspondente (403). Testes de fronteira: `tests/unit/local-session.test.js` “establishes a local session and requires its CSRF token for mutations”, “rejects insecure local origins on the HTTPS panel”, “accepts only the exact explicitly configured loopback HTTP origin for local Next development”, “rejects foreign Host and Origin values without reflecting them” e “requires a local session for administrative GET projections while keeping health reachable”. Idempotência é coberta por `queue-routes.test.js` “replays a mutation response for a repeated idempotency key without repeating its effect” e “rejects mutations that omit a valid idempotency key”. A idempotência das mutações de fila também vale para toda mutação `/api/*`, exceto `/api/session`: chave ausente/inválida ou armazenamento indisponível retorna 400/503; conflito de fingerprint ou operação em andamento retorna 409. Uma repetição restaura status/corpo salvos e adiciona `idempotency-replayed: true`; outros headers não são restaurados. Respostas >=500 não são salvas. Somente `expectedVersion` explicitamente indicado faz verificação de versão; sem ele, a rota/serviço de domínio é responsável por detectar conflito, e idempotência não implica concorrência otimista.

“Código/teste mapeado” significa que o handler e o teste nomeado foram inspecionados; isso não é evidência runtime. Os nomes indicam assertions disponíveis, não testes executados neste incremento documental. Todas as células runtime/browser seguem Pendente até serem executadas no ambiente isolado previsto. Este inventário não altera comportamento de rota, política de produto ou schema.
