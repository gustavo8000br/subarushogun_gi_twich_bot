# Verificação
[English](../../front-end-architecture/verification.md)


A matriz de migração OPS-15 mapeia cada tela/ação, endpoint da API, dependência de locale/catálogo, estado e ID de teste antes da remoção do frontend legado. O proxy dev do Next deve limitar-se a uma origem loopback validada, confiar na CA local gerada quando existir e ficar ausente da configuração de produção. Verifique a lista de rewrites de produção (API, API do overlay, saúde e callback para a origem Fastify HTTPS em loopback, e nada mais), o refresh direto de cada rota Next, que nenhum rewrite envie `/`, `/app.js` ou `/styles.css` ao Fastify (removidos na Onda 1 do cutover) e que nenhuma regra de desenvolvimento ou de produção reescreva ou redirecione `/overlay.html`, que recebe 404 do Next (alias removido na Onda 3 do cutover; `tests/unit/next-dev-proxy.test.js:56-61`, `tests/integration/compose-runtime.test.js:372-383`). Empacote e teste o mount somente leitura `.local/community-catalogs` em cada instalador unificado; adicione uma locale completa após o build da imagem e prove descoberta no painel/setup/chat na consulta seguinte e no overlay em até cinco segundos de cache. Testes também cobrem contratos de segurança same-origin, separação dos bundles painel/overlay, estados localizados de formulário/operação e critérios atuais de teclado, foco, contraste e WCAG AA do editor FND-7. Mantenha Host/Origin, sessão, CSRF, autorização, projeção de privacidade e correção das mutações sob testes de rotas/integração do backend.

Os contratos da fundação Next verificam inicialização da sessão antes das leituras protegidas, erros seguros do cliente API same-origin, headers CSRF/idempotência em escritas, atualização de idioma com revisão esperada, normalização de catálogos runtime e uso da projeção protegida de operador `GET /api/queues`. Projeção de fila inválida deve falhar de forma visível em vez de virar resumo zero. O fallback first-party pt-BR renderizado no servidor não substitui a descoberta runtime de catálogos nem a leitura do idioma persistido.

Os testes de navegador do overlay abrem o link exato do widget `/overlay?ref=...#token`, conferem que o alias aposentado `/overlay.html` recebe 404 sem redirecionamento (`tests/e2e/overlay-browser-only.mjs:47-52`) e cobrem remoção do fragmento, `sessionStorage` por ref, capability bearer sem sessão do painel, limpeza em 401/403/404, retenção de projeção stale, unload/reload e revoke/rotate. A evidência de desempenho mantém a meta FND-7 de oito fontes e dez atualizações em até dois segundos. Valide o servidor de produção do Next e o Fastify juntos em Compose isolado com PostgreSQL descartável. Evidências nativas OBS/CEF devem identificar plataforma e versões testadas; não alegue verificações não executadas.

Os contratos cobrem a configuração runtime do Next, arquivos de rota, a ausência de qualquer rewrite de `/overlay.html` (`tests/unit/next-runtime-config.test.js:38`, `tests/unit/api-static-surface-contract.test.js:41-52`), o formato do link do widget `/overlay?ref=...#token` (`tests/unit/overlay-widget-service.test.js:19-22`), bundles client por rota e a precedência Fastify para callback/API/health. O overlay Next dedicado monta o renderer existente, e o build Docker do frontend copia `apps/shared` e, de `apps/web`, somente os catálogos de localização (`Dockerfile:9-10`). Em produção, a `/` é respondida pelo Next, nunca pelo Fastify (`tests/integration/compose-runtime.test.js:372`). Os contratos do comando de desenvolvimento verificam que `npm run dev` configura portas separadas para API/frontend, bind da API em loopback, caminhos TLS, proxy same-origin e URL explícita obrigatória do banco; ainda é necessária uma execução integrada com PostgreSQL descartável antes de afirmar inicialização real dos dois serviços. O conflito de autorização/URL da OPS-13/#57 continua aberto; este incremento preserva o contrato atual de capability e não decide esse conflito.
